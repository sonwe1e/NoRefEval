rr_vfiqa

面向游戏视频插帧的多模式质量评测与问题诊断系统。自动选择安全模式、输出确定性分数与置信度、定位问题时间与空间位置、生成可直接查看的坏例证据。

开始评测 了解三种模式 报告阅读指南
Engineering quality / risk assessment Not human MOS Production gate: false

它解决什么问题

视频插帧模型生成的中间帧可能存在冻结、重影、撕裂、模糊、UI 不稳定等问题。rr_vfiqa 提供：

自动选择安全模式

根据输入视频的数量和帧率关系，自动判断能够安全使用的评测条件，无需用户手动选择。

确定性分数与置信度

输出 0-100 的质量分数和 0-1 的置信度，明确区分"视频表现如何"和"评测条件有多可靠"。

问题时间和空间定位

不只给出总分，还定位到具体的问题时间段和空间区域。

可直接查看的坏例证据

生成热力图、关键帧、Overlay/Compare 视频，让问题一目了然。

重要：三种模式的数学条件和评分标尺不同，overall_score 禁止跨模式比较。分数是工程风险等级，不是人类主观 MOS。

60 秒快速开始

pip install -e ".[torch]"

# 只有候选视频
rr-vfiqa inspect --candidate output.mp4 --out runs/nr

# 候选 + 参考（自动判断模式）
rr-vfiqa inspect --candidate output.mp4 --reference source.mp4 --out runs/example

三种评测模式

No-Reference
Endpoint-Referenced
Full-Reference

No-Reference

输入单条 60 或 120 FPS 视频
输出语义时序稳定性和伪影风险
Schemanr-stability-risk-v4
置信度三种模式中最低（上限 0.75）

核心方法：双相位自参考 + 公共物理时间尺度

Y0 ─ Y1 ─ Y2 ─ Y3 ─ Y4
└── phase A ──┘
     └── phase B ──┘

两个相位只作为对称假设使用，框架不会声称某一相位是真实帧。同时看 native、1/60 秒和 1/30 秒三档运动补偿残差。

能发现：冻结、交替模糊、抖动、UI 漂移、屏幕不稳定、cadence collapse

不能证明：真实运动轨迹、显露背景、hallucination 是否正确

Endpoint-Referenced

输入60 FPS 端点参考 + 120 FPS 候选
输出语义端点约束下的插帧质量
Schemaendpoint-reduced-reference-v3
置信度中等

核心模型：

X_i ── M_i ── X_{i+1}
真实端点  生成中间帧  真实端点

参考视频只提供端点，不提供真实中间帧。核心能力：

  • 双向 flow composition — 撕裂、错误运动层
  • Reverse anchor cycle — 时序不一致、系统性模糊
  • 运动补偿时序残差 — 拖影、闪烁
  • Edge support — 结构缺失、重影轮廓
  • UI/文字/人物代理 — HUD 漂移、笔画粘连

比 NR 可信，但仍不等于完整 GT。人物、细物体和 UI 仍属于代理分支。

Full-Reference

输入逐帧对应的 60 FPS GT + 60 FPS 候选
输出语义同帧空间、时序和运动保真度
Schemafr-same-rate-fidelity-v3
置信度最高

核心模型：

Reference_t  ↔  Candidate_t

要求逐帧对应。直接衡量空间、结构、时序和运动保真度。

几何策略：

  • strict（默认）— 要求原始宽高完全一致
  • resize-candidate — 显式把候选变换到参考工作网格
  • common-resolution — 把两路降到共同工作分辨率
注意：简单的"同一场景"不足以作为 FR。必须逐帧对应，否则会 fail-closed。

报告阅读指南

Overall Score

表示模式对应的工程质量或风险（0-100），不是 MOS。

Confidence

明确区分：

  • Score：视频表现如何
  • Confidence：本次评测条件和证据有多可靠

Status

ok核心流程完整
degraded部分阶段或媒体导出退化，但仍有有效结果
failed输入契约或核心指标不成立，不发布有效分数

Subscores

按模式动态展示。NR 包含 temporal_stability、motion_smoothness、phase_consistency 等；FR 包含 spatial_fidelity、structural_fidelity、temporal_fidelity、motion_fidelity。

Cadence（仅 NR）

  • Common-Time Quality：公共时间尺度质量
  • Cadence Integrity：相邻帧复制/冻结完整性
  • Cadence Risk：cadence 风险系数

Timeline 和 Issue Card

  • 颜色代表严重等级（severe / high / medium / low）
  • 轨道代表 Temporal、Motion、Structure、UI/Text 等问题域
  • 点击时间线跳转到问题卡片
  • 证据字段解释观测值与阈值
  • 可能原因标记为"推断"

常见问题

overall_score 是 null？

表示评测失败（status=failed）。查看 report.html 中的失败原因。常见原因：

  • 输入契约不成立（如 NR 模式下提供了 reference）
  • 对齐不可靠（FR 模式下帧率不匹配）
  • 核心特征缺失（视频太短或太简单）

两个模型的分数可以直接比较吗？

只有同一模式、同一参考、同一内容才可以比较。跨模式分数使用不同数学标尺，禁止直接排序。

可以只评分不导出视频吗？

可以，使用 --no-clips 跳过坏例视频导出，速度更快。

为什么 NR 的 confidence 比较低？

NR 无法证明真实轨迹或显露区域内容，因此 confidence 上限为 0.75。这是诚实的限制，不是缺陷。
